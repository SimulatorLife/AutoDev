# Improve one extensibility boundary

Identify one hard-coded decision point that genuinely limits supported flexibility, or one over-engineered extension seam that should be simplified back to an opinionated default. Make one focused change at the authoritative owner. Do not add speculative plugin systems, user-facing toggles, format autodetection, or compatibility fallbacks. Document the intended default and update focused tests or docs. Discover the target repository's own conventions and validation commands before editing.

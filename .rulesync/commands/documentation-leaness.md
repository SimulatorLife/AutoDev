---

Review one documententation-document in the codebase to identify and fix/improve **at least 5** instances of issues from amongst these categories:

1. Overly verbose language/wording/content is unnecessary, makes things *less* clear, and can be made more concise.
2. Important/useful/necessary detail is missing/omitted and should be added/restored to improve clarity, accuracy, and usefulness of the document.
3. Content/wording/section duplicates another part of the document or another document in the codebase and should be removed/combined.
4. Bad organization. Disparate things grouped together, sections that should be combined, things that belong in another section and should be moved, too many sections, etc.
5. Paragraphs that should be converted into a list or table to improve readability, conciseness, and scannability.
6. Things that are ambiguous, contradictory, or lack clarity, or are so vague that they are essentially meaningless and add no/less value as-is.
7. Inaccurate, outdated, or misleading information that should be corrected, removed, or flagged to the user (if ambiguity is present).

Leave inline comments, docstrings, and API reference tidy-ups to their dedicated workflow. Keep edits practical, concise, and easy to review so the documentation remains welcoming and trustworthy.

When done, perform one final review to ensure that all identified issues have been addressed and that no important/useful/necessary details from the original document(s) was removed/omitted and should be restored.

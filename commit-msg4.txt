refactor(console): one source for the navigation icon set

The nav icon list was written out twice -- once as a type union, once as a
`Set` literal of the same thirteen names -- so adding a resource to one left
the other stale, and which of the two you happened to edit decided whether it
typechecked. `NAV_ICON_SOURCES` now drives both, and `satisfies` pins every
entry to a name that actually exists in `ICON_PATHS`.

The new test asserts the invariant in both directions, because neither half
can catch the other: every canonical section resolves to an icon (a new
section with no glyph is otherwise invisible -- the link still renders and the
label still reads, so it only shows as one blunter sidebar row), and no nav
icon belongs to a section that no longer exists (a dead glyph is what lets a
future section borrow it by accident). It also pins that `navIcon` still
returns `null` for an unknown section rather than falling back, which is the
whole reason it exists.

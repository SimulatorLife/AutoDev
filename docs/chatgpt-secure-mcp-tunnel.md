# ChatGPT Secure MCP Tunnel

> **Target-state boundary:** This operational guide describes the current tunnel integration, not the final architecture. The [mandatory shared MCP gateway](autodev-console-target-state.md#mandatory-shared-mcp-gateway) is the canonical target: all AutoDev-managed provider MCP traffic must traverse Supergateway; the OpenAI tunnel becomes optional external ingress, independently managed. Direct provider stdio/backend HTTP connections are removed during migration. The checked-in runtime at this revision still uses shared stdio for the external tunnel; migrate to stateful Streamable HTTP with independent authenticated sessions (no stdio fallback) before claiming the gateway target is met. The commands below describe only that checked-in revision.

AutoDev can publish a single, private MCP tool catalogue to ChatGPT through OpenAI Secure MCP Tunnel. The `com.codex.autodev-chatgpt-tunnel` LaunchAgent supervises [Supergateway](https://github.com/supercorp-ai/supergateway) in loopback-only stateful Streamable HTTP mode (`127.0.0.1:3312` by default, `stateful: true`) alongside `tunnel-client`. Supergateway owns per-session MCP lifecycle (`Mcp-Session-Id` isolation with dedicated backend subprocesses per session), tool discovery, namespacing, filtering and routing; AutoDev owns configuration rendering, loopback binding, and per-generation local Bearer authentication. No non-loopback listener, public IP, port forwarding, or external gateway service is required.

## Installation (macOS)

Enable explicitly on the first normal install. Subsequent normal installs reconcile and restart the existing tunnel automatically; materialize-only installs never start or restart it. The installer taps `openai/tools` and installs the official Homebrew tunnel-client (minimum v0.0.21) when absent or outdated; Supergateway is an exact runtime dependency in `runtime/package.json` and is installed by the ordinary workspace package installation. It creates a dedicated login LaunchAgent and private local configuration; the runtime key is stored in macOS Keychain, not a plaintext runtime key file. The default workspace is the AutoDev checkout. Set AUTODEV_CHATGPT_MCP_WORKSPACE to an absolute project directory to select another workspace.

OpenAI requires organization-level tunnel authorization independently of ChatGPT subscription or plugin access. Obtain a restricted runtime key (Tunnels Read + Use) from [Platform organization API keys](https://platform.openai.com/settings/organization/api-keys). An existing tunnel must be associated with the intended ChatGPT workspace. If you already have an administrator key with Tunnels Read + Manage and explicit organization and workspace IDs, the installer can create the tunnel automatically:

```sh
# Supply these secrets securely through your shell, macOS Keychain, or a
# git-ignored .env file at the repository root (loaded automatically by
# scripts/install.sh via Node.js --env-file-if-exists; explicit shell exports
# take precedence). Never commit actual keys or put them in shell history.
# AUTODEV_CHATGPT_TUNNEL_API_KEY: restricted runtime key (required on first install)
# OPENAI_ADMIN_KEY: only for automatic tunnel creation
export AUTODEV_CHATGPT_ORGANIZATION_ID=org_...
export AUTODEV_CHATGPT_WORKSPACE_ID=ws_...
export AUTODEV_CHATGPT_MCP_WORKSPACE=/absolute/path/to/project
./scripts/install.sh --enable-chatgpt-tunnel
```

Alternatively create a tunnel in [Platform Tunnels](https://platform.openai.com/settings/organization/tunnels), then provide its ID using CONTROL_PLANE_TUNNEL_ID instead of the admin key (in the environment or repository-root `.env`). Organization and workspace IDs are still required to verify scope. The installer isolates tunnel credentials (`OPENAI_ADMIN_KEY`, `AUTODEV_CHATGPT_TUNNEL_API_KEY`) from dependency installation, materialization, and service restarts, stores `AUTODEV_CHATGPT_TUNNEL_API_KEY` in macOS Keychain (under service/item name `AUTODEV_CHATGPT_TUNNEL_API_KEY`, trusted for `/usr/bin/security` so the unattended LaunchAgent retrieves it across service restarts and system reboots without interactive prompts), configures `tunnel-client` with `--control-plane-api-key-ref env:AUTODEV_CHATGPT_TUNNEL_API_KEY`, and preserves the returned ID and policy file path for future installs. Existing plaintext `runtime.key` files are securely overwritten and removed automatically once migration to Keychain succeeds. It never stores or logs the administrator key. Do not supply an administrator key as the runtime key. The installer cannot grant account permissions or create a restricted runtime credential without prior OpenAI authorization.

## MCP access policy and single source of truth

AutoDev renders the Supergateway configuration from the installed `provider-runtime/mcp-servers.json` catalogue (derived from `.rulesync/mcp.jsonc`) and derives the external-access policy directly from canonical `.rulesync/permissions.jsonc` (covering read-only tools for `filesystem`, `lsp`, `cocoindex-code`, `codegraphcontext`, `openaiDeveloperDocs`, and `context7` — plus `googleDeveloperKnowledge` whenever `GOOGLE_DEVELOPER_KNOWLEDGE_API_KEY` is configured — while excluding `playwright`, `playtest`, `github`, `xacpx`, and `codex_app`). There is no duplicate MCP permission file; operators may optionally narrow grants with a private override JSON via `AUTODEV_CHATGPT_MCP_POLICY_FILE`. When `.rulesync/permissions.jsonc` or `provider-runtime/mcp-servers.json` changes, normal installs re-discover read-only tool inventories and reconcile automatically.

Canonical `.rulesync/permissions.jsonc` is the reviewed upper bound: server-wide grants (`mcp__<server>: { "*": "allow" }`) are restricted to tools advertising `readOnlyHint: true` during discovery, and tool-level grants (`mcp__<server>__<tool>: { "*": "allow" }`) authorize those explicit tools. To narrow grants, provide a private JSON policy file using `AUTODEV_CHATGPT_MCP_POLICY_FILE` (mapping server names to arrays of exact approved tool names; wildcards and empty lists are rejected, and a local override cannot widen `.rulesync/permissions.jsonc`). No gateway routing code changes are needed. The generated config preserves canonical commands/argument arrays for local backends and parameterized remote Streamable HTTP descriptors (`https://` URLs plus env/Keychain variable names only, never literal credentials in `supergateway.json`), selects the workspace as cwd, and assigns a server-specific `<server>__` tool prefix (`-` normalized to `_`). Static inline `env` credentials, non-HTTPS remote URLs, and unparameterized secret headers are rejected.

Supergateway receives a clean explicit environment rather than the tunnel client's environment. Local backends run inside macOS Seatbelt (`sandbox-exec`) profiles enforced by `externalMcpBackend`: `filesystem` runs strictly read-only on the selected workspace (`--read-only --confine-roots`, denying `.env*` except workspace `.env.example`, denying all writes and network); `lsp`, `cocoindex-code`, and `codegraphcontext` run their read-only query tools under Seatbelt profiles blocking workspace source edits, host secret paths (`.ssh`, `.aws`, `.gnupg`, `chatgpt-tunnel`, `.env*` except `.codegraphcontext/.env`), and non-local outbound network traffic. Remote Streamable HTTP documentation servers (`openaiDeveloperDocs`, `context7`) are bridged through `tool-filter.ts --remote`, which resolves only the declaring server's Keychain/env credentials (such as `CONTEXT7_API_KEY`) in memory without exposing secrets to Supergateway or sibling local servers. Session-bound, unconfigured-credential, or mutating backends (`codex_app`, `xacpx`, `playtest`, `googleDeveloperKnowledge`, `github`, `playwright`) remain unapproved unless separately reviewed and credentialed. Native OpenTelemetry export is implemented across all local and remote filtered backends.

The installer runs the pinned Supergateway binary's `--checkConfig` and a real Streamable HTTP SDK initialize/tools/list probe across independent client sessions, verifying unauthenticated `401` rejection, distinct `Mcp-Session-Id` isolation, the exact reviewed tool inventory, and rejection of unreviewed non-tool capabilities. It then generates the official `tunnel-client` Streamable HTTP profile (`sample_mcp_remote_no_auth`) pointing to `http://127.0.0.1:<mcpPort>/mcp`, runs `doctor` against an ephemeral candidate Supergateway (with `MCP_OAUTH_DISCOVERY=disabled` and `file:`-referenced `Authorization` headers), checks tunnel metadata with the runtime key, and requires launchd-owned readiness listeners for both `tunnel-client` (`3311`) and `supergateway` (`3312`). The previous profile and keys are retained until replacement succeeds, and existing stdio tunnel installations migrate automatically on normal `scripts/install.sh` runs. Supergateway binds exclusively to `127.0.0.1` using Streamable HTTP (not SSE) and requires a per-generation 256-bit `apiKeyFile` Bearer token. Supergateway 4.2.2 has a reported stdio-to-SSE denial-of-service vulnerability (CVE-2026-131857); that transport is not used here. Reassess the pin when updating dependencies.

## Attach ChatGPT

Once installation prints the ready tunnel ID, open ChatGPT Plugins > Add custom MCP server > Tunnel. Choose the AutoDev ChatGPT tunnel (or use the printed ID), choose no MCP-level authentication for this private stdio gateway, and create/install the plugin. The OpenAI tunnel itself authenticates the runtime. Verify by asking ChatGPT to list the allowed directories and read a known file in the selected workspace.

The service uses the dedicated label `com.codex.autodev-chatgpt-tunnel` (configured with `ProcessType: Interactive` so launchd does not throttle multi-backend session startup) and local health port 3311. Check:

```sh
curl -fsS http://127.0.0.1:3311/readyz
open http://127.0.0.1:3311/ui
launchctl print "gui/$(id -u)/com.codex.autodev-chatgpt-tunnel"
```

Generated `supergateway.json`, per-generation mode-`0600` local gateway auth files (`supergateway.key` and `supergateway-auth.header`), persisted gateway settings and logs reside under ${CODEX_HOME:-$HOME/.codex}/chatgpt-tunnel. The directory is private (`0700`) and the runtime credential (`AUTODEV_CHATGPT_TUNNEL_API_KEY`) is stored in macOS Keychain rather than in a plaintext file, injected only into `tunnel-client` at LaunchAgent startup (`env:AUTODEV_CHATGPT_TUNNEL_API_KEY`), and omitted from `supergateway` and MCP tools. Disable persistently with `./scripts/install.sh --disable-chatgpt-tunnel`; later normal installs honor that state. Re-enable explicitly with `--enable-chatgpt-tunnel`. Set `AUTODEV_CHATGPT_TUNNEL_PORT` to override 3311 and `AUTODEV_CHATGPT_MCP_PORT` to override 3312. Run `./scripts/install.sh --check` to check configured tunnel readiness and confirm no plaintext `runtime.key` remains. An interrupted install may leave an install.lock directory; remove it only after confirming no installer is running. Revoke the tunnel/key in Platform when no longer needed.

References: [OpenAI Secure MCP Tunnel](https://developers.openai.com/api/docs/guides/secure-mcp-tunnels), [official tunnel-client](https://github.com/openai/tunnel-client).

## Local protocol acceptance test

After the repository dependencies are installed, run `AUTODEV_TEST_SUPERGATEWAY=1 pnpm --filter @simulatorlife/autodev-runtime exec node --test tests/chatgpt-supergateway.integration.test.ts`. This uses the workspace-installed gateway (and the local `tunnel-client dev proxy` when `tunnel-client` is installed) to test its real stateful Streamable HTTP protocol—covering concurrent client sessions, repeated initialization, discovery followed by invocation, reconnection, and Supergateway restarts against the same running tunnel—and the actual workspace-confined AutoDev filesystem MCP, including out-of-workspace and symlink reads and direct calls to hidden write tools. It requires no OpenAI credentials; a separate authorized ChatGPT round trip is still required.

The existing AutoDev MCP tool filter runs in its external read-only profile before each approved backend. It denies non-tool RPC capabilities, normalizes read-only annotations, and reuses AutoDev's MCP OpenTelemetry span implementation with the private OpenLIT receiver key (and the LaunchAgent sets `MCP_FORWARD_TRACE_CONTEXT=true` so `tunnel-client` forwards incoming W3C trace context). The filter forwards tool results unchanged and never exports arguments or content. External initialize/list requests have a 15-second deadline, calls 60 seconds, and uncooperative cancelled backends are terminated after a five-second grace. Supergateway's stateful Streamable HTTP transport isolates each client session (`Mcp-Session-Id`) with its own backend processes and returns HTTP 404 for unknown/restarted sessions so clients cleanly re-initialize. Supergateway remains the sole aggregator; the reviewed policy is restricted to stateless, read-only tools until stronger per-server isolation is available.

## Console controls

After initial credential provisioning, the `/mcps` Console page displays tunnel readiness, the reviewed external policy and currently active grants. Operators can narrow grants, change the workspace, disconnect, re-enable, rotate the local restricted runtime key or forget that key. All mutations use the authenticated Control API with a revision check; the browser never receives the stored key. Forgetting the local credential does not revoke it remotely: use OpenAI Platform to revoke the credential or delete the tunnel.

Developer dependency update: after this change, regenerate the root `pnpm-lock.yaml` with the repository-pinned pnpm (`pnpm install --lockfile-only`), then run `pnpm install --frozen-lockfile`. The lockfile must be committed before merging; no separate Supergateway installation or lockfile is maintained.

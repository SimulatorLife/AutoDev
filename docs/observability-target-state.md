## 2. Goal, ownership, and topology

### Goal

Use standard OpenTelemetry traces, metrics, and logs as the telemetry contract and OpenLIT as the primary observability backend and UI. Avoid an AutoDev-owned observability database, general-purpose aggregation/query service, or parallel metrics dashboard. Preserve AutoDev-specific runtime controls through a small TypeScript Control API and isolated OpenLIT UI extension.

### Ownership

| Concern                                                         | Owner and boundary                                                                                                                                                                                                                                                                                                                                            |
| --------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| OTel semantics and context                                      | The component that owns the operation emits standard GenAI/MCP semantics and validated AutoDev context. Use a minimal `autodev.*` namespace only for genuinely AutoDev-specific concepts.                                                                                                                                                                     |
| Ingestion, storage, query, traces, and observability dashboards | Stock OpenLIT with its first-party OTLP receiver and storage/query/UI.                                                                                                                                                                                                                                                                                        |
| Generic dashboard variables                                     | A small, reusable, AutoDev-maintained OpenLIT UI/query-binding extension. It may add minimal generic query plumbing for safe typed bindings; it does not change telemetry meaning, storage schemas, or query semantics.                                                                                                                                       |
| AutoDev configuration and live control state                    | AutoDev’s typed Control API on a dedicated `/control`-only listener (default `4101` for the local OpenLIT container), called by isolated `/autodev` UI routes. The model/OTLP router remains on loopback port `4100`; the control listener requires service-token and viewer/operator allowlist checks. No telemetry or dashboard query is a command channel. |
| Additional standalone Collector                                 | Not part of the target by default. Add one only if a concrete policy need (for example redaction before export, routing, or fan-out) is documented and approved here.                                                                                                                                                                                         |

### Target data paths

```text
Observability:
AutoDev producers -- standard OTLP --> OpenLIT first-party OTLP/HTTP receiver
  --> stock OpenLIT storage, query, traces, and dashboards

Control:
Authenticated OpenLIT /autodev UI
  --> same-origin server-side proxy
  --> authenticated AutoDev Control API listener (control routes only; default port 4101)
  --> AutoDev runtime/configuration
```

Do not put a separate AutoDev Collector in front of OpenLIT’s first-party receiver. The current AutoDev Collector config has no processors and forwards OTLP to the router; it has no established permanent policy role.

## 3. OpenLIT UI and dashboard contracts

### Navigation and ownership

- Use OpenLIT’s stock observability UI and dashboards. Seed one **Usage** board; do not add a separate Analytics page.
- Use stock dashboards and trace views for historical Provider, MCP, Skills, and error analysis. OpenLIT 2.1.0 authenticates sessions but its Community Edition route-RBAC helpers are no-ops; enforce viewer/operator access in the AutoDev Control API.
- Keep AutoDev-only current state and actions under `/autodev` pages: **Providers**, **MCPs**, **Skills**, and **Runtime controls**. These pages show authoritative configuration, exposure/availability, and control state; they link to OpenLIT for historical activity rather than rebuilding charts.
- Keep trace exploration and session-level investigation in OpenLIT’s trace/log UI.

### AutoDev Usage board

The board is seeded by `patches/openlit/04-autodev-usage-dashboard.patch`. Every widget uses structured queries, the stock time range, typed variable bindings, and `service.name=autodev-router` so native provider CLI spans cannot duplicate router counts. Native provider CLI spans remain available in stock trace exploration with their resource context, but are excluded from these aggregate widgets; the Usage board counts the router’s canonical logical/attempt observations.

| Widget                         | Count/query semantics                                                                                                                                     | Variable opt-ins                                                                                           |
| ------------------------------ | --------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------- |
| Logical routed requests        | Count `autodev.routed_request` parent spans, including final failures; one count per logical route.                                                       | Workspace, requested model, agent/role. Provider is excluded because one route may use multiple providers. |
| Logical requests by agent/role | Count parent spans grouped by `autodev.agent.role`; this is routed-request activity, not unique agent sessions.                                           | Workspace, requested model, agent/role.                                                                    |
| Input / output tokens          | Sum reported `gen_ai.usage.input_tokens` / `gen_ai.usage.output_tokens` on physical `gen_ai.client_operation` spans.                                      | Workspace, provider, requested model, agent/role.                                                          |
| Cache-read rate                | `100 × sum(cache_read.input_tokens) / sum(input_tokens)` over attempts where both values are present. A missing/zero denominator is shown as unavailable. | Workspace, provider, requested model, agent/role.                                                          |
| P95 attempt latency            | P95 physical `gen_ai.client_operation` duration, not logical end-to-end latency.                                                                          | Workspace, provider, requested model, agent/role.                                                          |
| Physical attempts by provider  | Count attempt spans grouped by `gen_ai.provider.name`; compare with parent request count to inspect fallback/retry volume.                                | Workspace, provider, requested model, agent/role.                                                          |

The variable labelled **Requested model** uses `autodev.requested_model` on both logical and attempt spans; the physical target remains `gen_ai.request.model`. This keeps the cross-level filter accurate without redefining GenAI semantics. Tool/MCP operation charts and priced cost remain open until their source semantics and evidence are ready (G10).

### Dashboard variables

- Keep time range in OpenLIT’s existing time-range control; do not reimplement it as a custom variable.
- Add generic non-time variables for **workspace**, **provider**, **model**, and **agent/role**. A variable has a typed value source, supports single/multi-select and All, and persists selection in URL/dashboard state.
- A widget opts into the variables it uses. Selected values affect every opted-in widget consistently and do not affect widgets that do not declare them.
- The logical-request count intentionally does not opt into **Provider**: one logical request may have attempts at multiple providers. Provider filters apply to attempt-level widgets; routed-model, workspace, and agent/role filters apply at both logical and attempt levels.
- Bind values through typed, parameterized query inputs. Do not concatenate user-controlled values into SQL.
- The variable system remains schema-driven: AutoDev emits `autodev.workspace` as a stable privacy-safe workspace key and `autodev.agent.role` as a bounded role attribute. Generic OpenLIT variables accept a source/scope/key; they do not hardwire these AutoDev names. The pinned ClickHouse adapter advertises safely parameterized dashboard variables for traces; other signals must add their own binding support before they are selectable, and unsupported signal bindings fail closed.

## 4. Telemetry semantics and quality

### Request and trace accounting

A logical routed request and a physical provider/model attempt are different observations. Preserve them as a parent/child trace:

```text
AutoDev logical routed request (one count)
├── GenAI provider/model attempt 1 (one physical attempt)
└── GenAI provider/model attempt 2 (fallback/retry)
```

For a fallback such as OpenAI failure followed by Anthropic success, count one logical request and two physical attempts. Record provider reliability, attempt latency, tokens, and cost on the attempt that incurred them; record end-to-end duration and final outcome on the logical request. Do not copy attempt token/cost totals onto the parent and count them again.

The attempt span retains the caller’s routed model as `autodev.requested_model`; `gen_ai.request.model` continues to identify the physical upstream target. This AutoDev context is the Usage board’s model-variable key and must not replace or overwrite the standard attribute.

### Semantic conventions

- Prefer current official `gen_ai.*` and MCP semantic conventions for provider/model operations, agents, tokens, tools, MCP operations, errors, and duration.
- **MCP convention status:** the official MCP semantic conventions are pinned for this implementation to `open-telemetry/semantic-conventions-genai@bcc7f9c2856fa7f4feb753f54d4ebba9455cc3dc` (2026-09-29). They are marked Development, and that repository has no tags or releases; this is an intentionally experimental contract, not a stable OTel guarantee. Revalidate and update the pin/tests when changing producer semantics; optional upstream contribution never blocks AutoDev.
- Use `gen_ai.usage.input_tokens` and `gen_ai.usage.cache_read.input_tokens` for span-level cache accounting where emitted. Emit `gen_ai.client.token.usage` with `gen_ai.token.type=input|output` per physical attempt. Because the pinned GenAI metric convention has no cache-read series, AutoDev also emits `autodev.gen_ai.cache_read.input_tokens` only when the provider reports a valid cached-input count; it is a subset of input, never an additive total. Cache-read rate is cached input divided by input. Show unavailable—not zero—when the source does not report either value.
- Emit `gen_ai.client.operation.duration` once per physical provider/model attempt, and `autodev.router.logical_requests` plus `autodev.router.logical_request.duration` once per logical routed request. Keep request IDs and other per-request identifiers off metric dimensions.
- Use the minimal AutoDev skill contract because no suitable standard Skills semantic model is established. Emit one `autodev.skill` span per accepted observation with `autodev.skill.event` (`exposed`, `used`, `unavailable`, or `error`) and a path-safe `autodev.skill.name`; allow only bounded `autodev.skill.source` values (`role_contract`, `skill_read`). The `autodev.skill.events` counter has only event, validated workspace, and allowlisted role dimensions—never skill name, plugin ID, or request/session IDs. `exposed` means the bridge confirms that a role-contract skill was made available; `used` means an accepted/deduplicated confirmed use. The Control API reports declared role-contract inclusion (desired configuration), not proof that a CLI loaded the skill at runtime; do not label configuration as runtime enablement or infer either from exposure/use. Emit `unavailable`/`error` only when a producer reports that fact; missing events mean unknown, not disabled. Tests: `tests/router/router-telemetry.test.ts`.
- Attach provider, model, agent/role, and privacy-safe workspace context at the producer that knows it. Do not infer missing attribution downstream or adapt telemetry to fit a dashboard.
- A one-request bridge CLI may set workspace/role as resource attributes at its process-launch boundary through standard `OTEL_RESOURCE_ATTRIBUTES`; the multi-request router keeps per-request context on its spans. Do not promote a raw workspace path or copy unknown values as a fallback.
- Keep request, session, conversation, thread, trace IDs, raw paths, and URLs out of metric dimensions. Use trace/span/log context for session-level queries. Metric dimensions must remain bounded and stable.
- Never export secrets, raw prompts/responses, credentials, or raw tool arguments. Distinguish unknown/unattributed/unavailable from zero. Preserve source timestamps and deduplicate retries/redelivery at the operation owner.

## 5. AutoDev Control API and authorization

The current provider-admin route is not a unified control API. The target resource model is:

| Resource  | Read state               | Mutation contract                                                                                                                                 |
| --------- | ------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------- |
| Providers | `GET /control/providers` | `PATCH /control/providers/{provider}/roles/{role}` with a typed desired-state field; migrate the existing provider/role enablement here first.    |
| MCPs      | `GET /control/mcps`      | Read-only until the authoritative writable configuration and apply lifecycle are identified; then add explicit resource-specific operations only. |
| Skills    | `GET /control/skills`    | Read-only until the authoritative writable configuration and apply lifecycle are identified; then add explicit resource-specific operations only. |
| Runtime   | `GET /control/runtime`   | Expose live operational state. Add only named, typed operations with an identified owner; no arbitrary command endpoint.                          |

The OpenLIT browser must not call the Control API directly. A same-origin OpenLIT server-side proxy must authenticate the user session, enforce CSRF protection, apply authorization, and call the private AutoDev API with a scoped service credential and verified actor identity. OpenLIT runs in a container and cannot rely on the router's loopback-only port `4100`; the router therefore exposes a separate listener, default `4101`, that serves only `/control/*`. It is enabled for OpenLIT ingress by `scripts/run-codex-model-router.sh`; the model/proxy and OTLP paths remain on the loopback listener. Configure `host.docker.internal` to the host gateway for the OpenLIT container. The Control API independently validates service credential, verified actor, and resource/action scope. Use **viewer** access for reads and **operator** access for mutations. The dedicated listener is not user authorization by itself: retain the strong service token and actor allowlists, and apply host firewall policy appropriate to the deployment. If the selected OpenLIT deployment cannot establish an authenticated identity, keep mutations disabled until an explicit local authentication path exists.

Record each attempted mutation’s actor, resource/action, requested change, and outcome in a redacted audit record. After the operation, emit `autodev.control.mutation` with only action, resource, outcome, actor role, and bounded error type; never put the actor ID, bearer token, or raw mutation body in OTel attributes. OTLP ingestion, dashboards, and query execution remain read-only. Verify this in `tests/router/control-api.test.ts`.

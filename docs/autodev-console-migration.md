# AutoDev Console Migration Tracker

> **Scope:** Current implementation state, gaps, cutover dependencies, and acceptance evidence for the AutoDev Console/OpenLIT migration.
>
> **Authority:** [autodev-console-target-state.md](autodev-console-target-state.md) is authoritative for product, architecture, UI, ownership, and correctness requirements. This file records only observed implementation state and remaining migration work.
>
> **Last reviewed:** 2026-10-06.

## Current baseline

The repository is on the four-workspace TypeScript layout (Console, Runtime, Core, Data) and the obsolete root implementation tree is gone. OpenLIT plus the AutoDev Control API are the target observability/control foundation, but the migration is not complete: the unified Console still lacks full feature parity, the OpenLIT product shell still contains unwanted generic product code, RuleSync role/permission parity is incomplete, and router-owned direct OTLP/history paths remain.

The active local OpenLIT baseline is:

- upstream OpenLIT openlit-2.1.0 at commit 9938c66638666ca5d3bcb850350faa82e510924b;
- published baseline image ghcr.io/openlit/openlit@sha256:94552ccd09379b5e2fec3c51c4fec1b41d88d6b56b0a5ccc895c116673884fa8;
- active local patch level p25, image autodev-openlit:openlit-9938c6663866-pd8ea85e2259187eb;
- active local image digest sha256:fabd1db9f0ce2f840c738e532d94bdc5937efaf8942dc41120fb02547337de75;
- standard lock at $CODEX_HOME/openlit-patched.lock;
- telemetry retention 730 hours (about 30 days), with durable local volumes and no automated backup.

Local p25 acceptance has verified the OpenLIT container, /memory HTTP 200, unauthenticated OTLP rejection, authenticated content-free OTLP acceptance/persistence, live Usage filtering, and service-token redaction. Remote deployment acceptance remains open.

This inventory is **observed current state**, not the desired API family from the target document.

Current read-only collection GETs:

```text
/control/agents

/control/runtime
/control/evaluations
/control/github
```

Current read-only detail routes include Agent, Prompt, and committed Prompt version detail; Prompt version history is a read-only collection subresource. General collection resources reject non-GET methods.

`/control/providers` v2 returns each provider's route, credential presence, role enablement, tier models, priority groups, orchestrator reasoning effort, and live router health (`null` when the router has not registered evidence). `/control/models` v2 lists each model `config/model-routing.json` maps a provider tier to, with its provider, tiers, Codex-catalog display name, and enablement.

Current non-Memory mutations:

```text
PATCH /control/providers/:provider/roles/:role
PATCH /control/models/:model
```

Both accept only `{"enabled": boolean}` from an operator, change Runtime routing-policy state, persist it, roll back on persistence failure, and audit the change.

Memory is a separate governed family under `/control/memory/*`. Implemented resources include records, experiences, experience history/provenance and lifecycle actions, experience/session/use cohorts, native Codex/Claude capture paths, reporter-supplied outcome routes, curator use-assessment routes, guarded raw-experience purge, and procedure-to-skill promotion. Those operations remain subject to MemoryService authorization/governance rather than becoming generic Control API CRUD.

`/control/github` is implemented as an authenticated read-only `GET` collection returning the parsed `.github/workflows/*.yml` workflow-definition/event/cron catalog (`schema: autodev-control-github-v1`, `readOnly: true`); it strictly rejects non-`GET` methods with HTTP 405. When server-side `AUTODEV_GITHUB_TOKEN` is configured and `AUTODEV_GITHUB_REPOSITORY` is validated against an enabled canonical workspace in `config/workspaces.json`, the endpoint additionally surfaces authoritative workflow enabled state (active vs disabled) and a bounded 30-run sample with scoped statistics via the typed Data adapter (`GithubActionsAdapter`). Invariants enforced: fixed `https://api.github.com` origin, redirects denied (`redirect: "error"`), path segments encoded with `.`/`..` rejected, streamed 1MiB response body limit with active timeouts, fail-closed handling for malformed records, oversized error bodies preserving HTTP auth/rate status, workflows capped at 100 with partial status if exceeded, and `successRate` denominator = all sampled completed runs (in-progress excluded; non-success/missing conclusions in denominator; null when 0 completed runs in sample). Missing credentials, unconfigured/disabled repository scopes, or GitHub API failures render as explicit `Unavailable`/`Invalid` status without synthesizing health or zeros. No dispatch/cancel/rerun/schedule mutations are implemented (non-`GET` returns HTTP 405); live production-credential, remote-deployed, and browser-rendered acceptance remain open. General RuleSync/runtime mutations and reusable desired/actual reconciliation are also still incomplete.

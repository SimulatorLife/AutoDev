# AutoDev Console Migration Tracker

> **Scope:** Current implementation state, gaps, cutover dependencies, and acceptance evidence for the AutoDev Console/OpenLIT migration.
>
> **Authority:** [autodev-console-target-state.md](autodev-console-target-state.md) is authoritative for product, architecture, UI, ownership, and correctness requirements. This file records only observed implementation state and remaining migration work.
>
> **Last reviewed:** 2026-10-06.

## Current baseline

The repository is on the four-workspace TypeScript layout (Console, Runtime, Core, Data) and the obsolete root implementation tree is gone. OpenLIT plus the AutoDev Control API are the target observability/control foundation, but the migration is not complete: the unified Console still lacks full feature parity, the OpenLIT product shell still contains unwanted generic product code, RuleSync role/permission parity is incomplete, and router-owned direct OTLP/history paths remain.

The active local OpenLIT baseline is:

- upstream OpenLIT openlit-2.1.0 at commit 9938c66638666ca5d3bcb850350faa82e510924b;
- published baseline image ghcr.io/openlit/openlit@sha256:94552ccd09379b5e2fec3c51c4fec1b41d88d6b56b0a5ccc895c116673884fa8;
- active local patch level p25, image autodev-openlit:openlit-9938c6663866-pd8ea85e2259187eb;
- active local image digest sha256:fabd1db9f0ce2f840c738e532d94bdc5937efaf8942dc41120fb02547337de75;
- standard lock at $CODEX_HOME/openlit-patched.lock;
- telemetry retention 730 hours (about 30 days), with durable local volumes and no automated backup.

Local p25 acceptance has verified the OpenLIT container, /memory HTTP 200, unauthenticated OTLP rejection, authenticated content-free OTLP acceptance/persistence, live Usage filtering, and service-token redaction. Remote deployment acceptance remains open.

| Console                | **Runnable foundation; 13/13 routes**                                                              | `console/` ships all 13 canonical resource routes. Providers (`/providers`, listed after Agents under Configure) has URL-addressable Providers and Models tabs plus provider detail (`/providers/:id`) and model detail (`/providers/:id/models/:model`) pages. Controls are contextual: each provider's orchestrator/subagent toggles sit on its Providers row and on its detail page, and each model's toggle sits on its Models row, on its detail page, and in its provider's model list. Every placement renders one shared toggle that posts a bounded same-origin form to a typed Console route (`/api/providers/:provider/roles/:role` or `/api/models/:model`), which calls the Control API and redirects back to the originating Providers page, or adds a could-not-be-confirmed notice; unchangeable or unobserved state keeps the control in place, disabled, with the reason. Provider rows and detail show route, credential presence (never values), tier models, priority groups, orchestrator reasoning effort, and live router health (cooldown, failure streaks, in-flight requests, active agents, attempts, last success/failure), or `Not observed` without router evidence. Agents list and detail now show read-only provider summaries for the agent's role kind that link to Providers. Priority/fallback groups and per-tier model mapping are shown read-only: they are owned by `config/model-routing.json`, and Runtime has no typed mutation or reload path for them yet. `/github` is a native read-only surface paired with authenticated GET-only `/control/github`, displaying the parsed workflow definition/event/cron catalog alongside authoritative read-only Actions runtime state (active vs disabled) and bounded 30-run sample statistics via `GithubActionsAdapter` when server-side credentials and an enabled canonical workspace are configured, or explicit `Unavailable`/`Invalid` status without synthetic zeros. Agents provider-role views render `Not observed` when provider configuration is absent rather than defaulting to enabled or disabled. MCP list/detail role columns describe configured assignments and explicitly state when no roles are assigned; they do not claim runtime exposure. The Skills view now renders the complete RuleSync skill catalog with source descriptions and paths joined to execution-contract role assignments from `/control/skills` v2; it preserves absent/invalid source state, surfaces assignments with no canonical skill, counts only catalog-backed role assignments, and keeps selection/exposure/use unknown without runtime telemetry. The RuleSync repository distinguishes an unobserved directory, a valid empty catalog, and malformed/symlinked skill sources; the catalog's source descriptions are parsed from valid Markdown YAML frontmatter. The catalog and role eligibility are read-only today; canonical skill edit/enablement, validation, generation, and apply workflows remain open. Prompts now use a single Data-owned RuleSync frontmatter reader for Console and OpenLIT sync; the Console gets source-authored descriptions and `/control/prompts` v2 reports absent/invalid command catalogs instead of fabricated empty lists. Prompt command detail now edits canonical Markdown and submits same-origin `POST` to typed `PATCH /control/prompts/:name` with an expected-source revision. Runtime validates/atomically updates the RuleSync file, regenerates and applies the Codex command projection, audits only bounded metadata, and reports restart-required projection changes; role prompts remain read-only. Command detail now renders the parser-owned Markdown body safely (raw HTML is not enabled), lists up to 20 committed Git versions, and shows a selected revision's bounded unified diff against the current working tree; missing Git history stays explicitly unavailable. Older-history paging, richer preview for unsaved edits, role prompt editing, and reusable operation/convergence history remain open. The shared DataTable now supports opt-in wrapped cells; long Skills/Prompts/Tools/Workflow metadata no longer forces the table wider than its viewport. Usage formats grouped counts, compact token totals, and unit-scaled percentile durations for readability, and names empty role/provider/tool groups `Not attributed`. Agents are read-only in both the list and the detail view, and no mutation is offered, because the Runtime has no agent enablement to offer: `/control/agents` answers `autodev-control-agents-v1` with `readOnly: true` and each record carries no `enabled` field, and no `/control/agents` mutation route exists. Adding it needs a Runtime-side enablement concept first; a Console-only control would have nothing to call. (An earlier revision of this tracker claimed an Agents list enable/disable route existed. It does not: there is no `console/app/api/agents` route and no enablement control in `AgentsView` or `AgentDetailView`, and the claim has been corrected here.) Finish shared design-system consistency, retained-feature parity, real states/data, production lifecycle, and removal of transitional OpenLIT fallbacks; keep GitHub strictly read-only per the target.
```text
PATCH /control/providers/:provider/roles/:role
PATCH /control/models/:model
```
